# 06 · Техническое задание: приложение «Аптайм»

06 · Техническое задание: приложение
«Аптайм»
Нативное приложение: сервер + клиент бригады. Сборка .exe, self-contained, запускается на
конкурсном компьютере без установки.

1. Назначение
Приложение ведёт смену: показывает состояние (код, бригады, очки, время, очередь), принимает
карты от бригад, запускает полигон и фиксирует результат. Преподаватель им не «управляет
уроком» — он ведёт смену, а приложение держит счёт.
Не является: IDE, обучающей платформой, тестом, системой проверки знаний.

Принципы:
1. Сервер — единственный источник истины. Клиент не считает очки.
2. Отключение клиента не останавливает смену: пропущенный ход восстанавливается после
переподключения.

3. Все экраны обновляются одним событием состояния, а не набором команд.

4. Вход и подключение
•  Вход: 4-значный код партии + выбор бригады + выбор роли.
•  Код показывается на экране зала крупно.
•  Один человек — одна роль; повторный вход с той же ролью вытесняет предыдущую сессию.
•  Ведущий входит по отдельному постоянному коду; арбитр — по коду партии с меткой роли.

5. Экраны
5.1 Экран зала (сцена)
Зона Содержимое
Слева, ~62 % монитор: код сервиса, номера строк, подсветка
проблемных, пометки
Справа, ~38 % вертикальная приборная панель: три пластины
бригад, наряд-задание, блок времени
Низ лента событий: карты, запуски, вердикты

Состав панели:
•  Пластина бригады: латунная табличка с названием, клеймо формы (треугольник /
шестиугольник / квадрат), чип статуса, лампы жизни, крупная цифра очков.
•  Наряд-задание: «выбери патч», строка атаки моно, награда, подвал со сроком и ролью.
•  Блок времени БВ-1: семисегментные цифры, ролик фазы, шкала с красной зоной, клавиши.
5.2 Клиент бригады
Зона Содержимое
Верх бригада, роль, таймер такта
Центр поле карты: строка, тип, формулировка (одно
утверждение)
Право история боя: что заявлено, что проверено
Низ кнопка «Отправить» и статус вердикта

Карта отправляется один раз. Редактирование после отправки запрещено — это воспитывает
точность формулировки.
5.3 Панель арбитра
•  Карты атакующей и защищающейся стороны рядом.
•  Поле вердикта: ПРОБИЛА / ОТБИТА / НЕ ПРИНЯТА (с причиной).
•  Журнал: автоматически подставляется строка, арбитр дописывает формулировку.
•  Кнопка «Найти пропуск» — очко арбитру.

5.4 Панель ведущего
Фазы, таймер, счёт, ручная правка очков (с записью в журнал), переключатель режимов, показ кода
партии, аварийный переход к старту.

7. Полигон: как устроен живой запуск
Полигон — не полноценная IDE. Это песочница с подготовленными слотами патчей, чтобы на
конкурсе не тратить время на синтаксис.
Полигон «Партер»
├── Program.cs      сценарий: очередь из 1240 записей
├── Booking.cs      разбор брони (строка 12 — FormatException)
├── Pricing.cs      расчёт цены (строка 31 — DivideByZeroException)
├── Seats.cs        места (строка 8 — IndexOutOfRangeException)
└── Promo.cs        промокод (строка 19 — NullReferenceException)
Четыре слота патча, вставляемые клавишами 1–4:
Слот Патч Что делает
1 try { ... } вокруг вызова ловит первое исключение
2 catch (Тип) добавляет обработчик
конкретного типа
3 finally { ... } гарантирует закрытие
4 throw; / throw ex; / отчёт честная запись вместо
проглатывания

Запуск — Enter. Результат — ПРОБИЛА или ОТБИТА, с указанием строки и типа.


8. Горячие клавиши
Клавиша Действие
Пробел пуск / пауза таймера такта
1 2 3 выбрать бригаду
Y / N ПРОБИЛА / ОТБИТА (арбитр)
Q «найти пропуск» (арбитр)
R следующий такт

Все действия дублируются мышью. Ни одно действие не требует ввода текста на скорость.

11. Что не входит в MVP
•  Компиляция произвольного кода от участников (только слоты патчей).
•  Личные кабинеты, статистика между уроками, база групп.
•  Голосовой чат и видео.
•  Мобильная версия.
•  Экспорт в учебный журнал.

12. Этапы
Этап Результат

2 клиенты бригад, вход по коду, карты
3 полигон: четыре слота патчей, живой запуск
4 старт в 09:00, табло очереди, протокол смены
5 режимы Ручной и Автономный
6 тема оформления: тёмная и светлая
